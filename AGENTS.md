# Agents

## Generated content

`_activities/` contains cached Strava activity JSON. Activity posts in `_posts/` are generated by `_lib/post.rb`; tag pages in `tags/` and `_data/tags.yml` are generated by the `tags` rake task. Change the generator for lasting behavior changes, then update existing content as needed.

For tag-only backfills, match activities to posts by `strava_id`, not filename: sport types can change, leaving different activity and post filenames. Preserve post bodies, photos and formatting.

## Shoe tags

Use `s/YYYY/MM/<full lowercase gear name>` for individual shoe tags and retain existing brand tags. The year/month is the pair's first recorded use across cached activities, matched by gear ID, not the year of each run or a purchase date. `_lib/shoe_tags.rb` shares this calculation with the post generator. If an earlier activity is added, update all affected post tags and photo mappings together. Key `_data/shoes.yml` by the exact tag. Do not guess which pair an ambiguous photo belongs to; ask for the model or tag.

## Shoe photos

Save shoe photos locally in `images/shoes/` and map them to exact `s/` tags in `_data/shoes.yml`. Do not fetch images during site builds.

Transform supplied product photos to have white backgrounds before adding them. Preserve the shoe's colors and shadows; use a connected-background flood fill rather than replacing similar colors throughout the image. For the light gray backgrounds used by the current Adidas photos:

```bash
magick input.jpg -fuzz 3% -fill white -draw 'color 0,0 floodfill' -quality 95 output.jpg
magick output.jpg -fuzz 5% -trim +repage -bordercolor white -border 10 -quality 95 output.jpg
```

Crop excess background around the shoe, retaining its shadow and a small white border, so bottom-positioned product photos are centered in thumbnails. Inspect the result visually. Crop screenshots to the shoe photo only, excluding purchase details. Keep the shoe's aspect ratio; the shoes page displays a 48x48 thumbnail and a larger hover/focus preview. Shoes without photos use a transparent 48x48 spacer.

## Strava updates

Refreshing local data and changing activities on Strava are distinct operations. Do not write to Strava unless requested. When assigning gear, stop on a conflicting existing assignment and verify the saved gear ID before refreshing local JSON and posts.

Use targeted updates for existing activities, such as `ID=<activity-id> bundle exec rake strava:update_one`. The current `strava:update` date-range task deletes local files before rewriting them, requests activities without an upper date bound, and can stop prematurely when newer activities arrive first. Fix that behavior before relying on it for historical refreshes.

Strava refreshes can change photos and other metadata beyond gear. Review the resulting diff and confirm unexpected content removals before publishing.

## Validation

Regenerate tags after changing post tags:

```bash
bundle exec rake tags
```

Regenerate summaries with `bundle exec rake prs` when relevant. Before publishing, run:

```bash
git diff --check
bundle exec jekyll build --quiet
```

Verify generated shoe pages, exact tag-to-image matches, local image paths and tag link targets. Keep task-specific instructions, such as whether to commit, out of this file.
